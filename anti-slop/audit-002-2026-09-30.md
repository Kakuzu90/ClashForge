## Findings

1. HIGH. UiButton.vue:44-46,50; UiInput.vue:45; UiModal.vue:58; UiToast.vue:34; UiPill.vue:41,57;
   Pages/Dev/Components.vue:53. R-03 (tap targets 44px; layoutmobile "Under-Sized Targets"; spec 18
   §8 and §5 mobile). sm/md buttons are 32/40px, input 40px, modal close 40px, selectable pill 28px,
   pill remove button 20px, gallery nav links about 28px. Spec 18 §4 sizes (32/40/48) and §8 (44
   touch minimum) collide, and no mobile floor exists. Fix: below the `sm` breakpoint raise these
   to `min-h-11`/`min-w-11` (or add a 44px hit area via padding or a pseudo-element) and keep the
   spec sizes from `sm` up; give the pill remove button at least 8px separation from its pill.

2. MEDIUM. UiAvatar.vue:34,46. R-06 (typography must improve readability; spec 18 §3 "display font
   never below 16px"). Initials use `font-display` at `0.4 * size`: 10px at 24, 13px at 32, 19px at
   48. Two of three small sizes break the display-font floor and are hard to read. Fix: use
   `font-body font-semibold` (Inter) below 48px with a 12px floor, or hide initials at 24px.

3. MEDIUM. UiToast.vue:8-13,26-29. R-01 / C-4 (antislop-human "Color-Only Feedback"; DESIGN.md
   "always paired with a label"). Sighted users tell info, success and danger apart only by the
   left-stripe colour; the kind label is `sr-only`. Fix: show a visible kind marker (short icon or
   visible label beside the title) so the stripe reinforces rather than carries the state.

4. LOW. UiButton.vue:73-79. C-4 / R-27 (antislop-human "Missing UI States"). When `loading`, the
   label span is `invisible` (visibility hidden removes it from the accessibility tree), so the
   button's accessible name becomes "Loading" and the action name is lost. Fix: hide the label
   with `opacity-0` (stays in the tree) and keep the sr-only "Loading" as an addition, not a
   replacement.

5. LOW. UiInput.vue:60; UiTextarea.vue:53. C-2 / C-4. `v-bind="$attrs"` on the inner control
   without `inheritAttrs: false`, so class, name, placeholder, autocomplete and data-* land on the
   wrapper div and on the control. The gallery's `class="sm:col-span-2"` on UiTextarea is applied
   twice as a result. Fix: `defineOptions({ inheritAttrs: false })`, put `$attrs.class`/`style` on
   the wrapper and the rest on the control.

6. LOW. UiModal.vue:23-25; useFocusTrap.ts:66. C-4. The scroll lock has no unmount cleanup, so an
   Inertia visit while the modal is open leaves `body` at `overflow: hidden`; both the lock and
   the trap watch `open` without `immediate`, so a modal mounted already open gets neither. Fix:
   add `onBeforeUnmount` to reset overflow and run the watchers with `immediate: true` (client
   only).

7. LOW. UiToaster.vue:10. C-4 / R-32. `aria-label="Notifications"` sits on a plain div, which
   assistive tech ignores; the comment calls it a region. Fix: add `role="region"`.

8. LOW. useToast.ts:40-43. C-4 (timing adjustable). Toasts auto-dismiss after 5s with no pause on
   hover or focus, so a reward toast with body text can vanish mid-read. Fix: pause the timer on
   `mouseenter`/`focusin` inside the toast and resume on leave, or keep body toasts until dismissed.

9. LOW. UiInput.vue:48,62. C-4. Prefix and suffix are `aria-hidden`, so a unit or symbol such as
   "px" or "#" is invisible to screen readers and the value is announced without it. Fix: include
   the unit in the hint or label, or expose it via `aria-describedby`.

10. LOW. UiSkeleton.vue:11; UiAvatar.vue:42. R-27 / C-4 (antislop-human "Missing UI States"). The
    loading states are `aria-hidden` with no text alternative, so a screen-reader user sees an
    empty region. Fix: add an optional `label` prop rendered as `role="status"` sr-only text on the
    skeleton and avatar loading variants.

11. LOW. UiCard.vue:25. C-4. `aria-current="true"` marks a selected card; `aria-current` means
    the current item in a set (page, step), not a selection, so "selected" is never announced.
    Fix: drop it and put `aria-pressed`/`aria-selected` on the actual control inside the card, or
    accept a `selectedLabel` sr-only text.

12. LOW. UiButton.vue:39-40. C-2 (spec 18 §4 lists a hover state for every button). Danger and
    success have no hover style while primary, secondary and ghost do; `--brand-primary-press`
    is defined but no `active` style uses it. Fix: add hover fills using the 400 shades (verify
    dark text contrast with contrast-check.py) and use `brand-press` on primary `active`.

13. LOW. Pages/Dev/Components.vue:46. R-25 / spec 18 §3 ("muted text is never used below 14px").
    "Dev only" is `text-xs text-fg-muted` (12px). Contrast passes (6.12), the size rule does not.
    Fix: use `text-sm`, or `text-fg-secondary`.
