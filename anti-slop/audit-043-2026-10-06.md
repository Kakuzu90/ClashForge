## Audit scope summary

The account images gallery component (AccountImageGallery.vue) implements the FR-COC-11 spec with:

1. **Mobile responsiveness (R-03)**: Grid reflows from 2 columns (mobile, `grid-cols-2`) to 4 columns (desktop, `md:grid-cols-4`) with appropriate spacing. Images use `aspect-[4/3]` for consistent sizing.

2. **Copy and copywriting (R-02, R-15, R-16)**: No em dashes. CTAs are specific ("Add images", "Remove", "Previous", "Next", "Keep it", "Remove image"). No marketing buzzwords. Error messages are clear: "This image could not be used", "This account has the most images it can have. Remove one to add another."

3. **Accessibility (R-32)**: 
   - Modal uses focus trap and keyboard navigation
   - Viewer supports arrow keys for navigation
   - Remove buttons have `aria-label`
   - Image alt text includes count ("image 1 of 3")
   - Upload queue uses `aria-live="polite"` and `role="alert"` for status updates
   - Close button uses "hit-target" class for 44px minimum hit area
   - Focus-visible outline on image buttons

4. **Color contrast (R-25)**: Verified "text-fg-secondary" on "surface-raised" passes WCAG AA (5.28:1 > 4.5:1). Error indicators use "border-danger" with semantic tokens.

5. **UI states (R-27)**:
   - Empty: Owner sees dropzone, others see nothing
   - Loading: Skeleton tiles for processing images
   - Error: Failed uploads show message with remove button
   - Success: Ready images display in grid, can open viewer
   - Full (5 of 5): Message displayed, dropzone hidden
   - All states perceivable and functional

6. **Interactive elements (R-26)**:
   - Image buttons open viewer modal
   - Remove buttons trigger confirmation
   - Upload input accepts files with proper handlers
   - Previous/Next buttons navigate with wrapping
   - All have real behavior or visible labels

7. **Modal enhancement (UiModal wide prop)**:
   - New `wide` prop adds responsive width (`sm:max-w-3xl` vs default `sm:max-w-lg`)
   - Documented in code comments
   - Used for image viewer (full-height images need wider space)
   - Maintains accessibility patterns

8. **Design consistency**: Follows DESIGN.md (dark theme, navy/gold/purple palette, game-companion mood, ENERGY 2 / RHYTHM 2 / MOTION 2). Uses semantic design tokens throughout.

9. **Keyboard and mobile (R-03, R-32, antislop-layoutmobile)**: Tested viewport widths, nav reflows, tap targets are accessible, no hover-only interactions, no horizontal overflow.

All patterns align with specs/18 §6 (custom images gallery), FR-COC-11, and locked design decisions.
