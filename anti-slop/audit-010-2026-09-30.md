### Rationale

**Copy & text (antislop-copywriting):**
- All user-facing text is specific and clear: form labels ("Display name", "Bio"), hints ("Use your YouTube handle, like @clashchief"), status messages ("Saved."), validation messages ("Choose a country from the list.")
- No em dashes (R-02). No buzzwords or generic language (R-16). No fabricated claims (R-36).
- CTAs are specific ("Save profile", "Upload photo", "Change photo"), not generic (R-15).
- Error and status messages are actionable: "This upload was made for something else. Upload the file again." explains the problem and what to do.
- Tone is plain and instructional, matching the ENERGY 1 work surface (R-37).

**UI & visual (antislop-ui):**
- No template layouts (R-05). Settings layout is custom sub-nav + content, designed per specs/18 §6.
- Semantic tokens only; no arbitrary colours (Tailwind 4 tokens: navy, gold, purple accent, functional state colours per DESIGN.md).
- No excessive decoration: no gradients without purpose (R-01), no glow/shadows/glass as default (R-10, R-12, R-13).
- Mobile-first responsive grid (R-03). Border radius is consistent per design system (R-11).
- Avatar field shows full state coverage: uploading, processing, success, error, and stored states (R-27).
- All interactive elements have real behavior: buttons submit or navigate, links go to real pages (R-26).
- Motion dial (MOTION 1 per DESIGN.md): hover states only, no page transitions or endless animations (R-19).

**Code comments (antislop-code):**
- All comments add information the code does not show. Examples:
  - "One select per language slot keeps the form keyboard-simple; empty slots are dropped on save." explains a UX decision (R-31).
  - "Avatar upload (FR-PROFILE-3): the file goes to storage through useUpload, and once it is ready the profile is pointed at it. The server checks ownership, collection and status again." explains the two-step process and security (R-31).
  - Comments reference specs (specs/18 §6, specs/04) and task numbers (P1-03, P1-05), providing context (R-31).
- No decorative separators, no restating the obvious, no vague TODOs, no emoji.
- Comment density: one substantive comment per logical section, not per line.
