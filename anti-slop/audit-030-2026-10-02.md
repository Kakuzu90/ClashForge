### Audit notes

#### Copy & tone (R-02, R-15, R-16, antislop-copywriting)
- Banner messaging is simple and specific:
  - "Clash of Clans is down for maintenance" / "not answering right now" (clear alternative reasons)
  - "Game data may be a little out of date, and verifying accounts is paused until it is back" (explains consequence)
- Paused verification messages ("Verification is paused", "Nothing you entered is lost") are reassuring without hedging
- Dashboard panel description ("Our calls to the game API") and empty state ("No calls in the last N hours") are descriptive, not buzzwords
- No em dashes detected anywhere in UI text or copy
- No generic CTAs; all actions are context-specific ("Verify with token", "Try again")

#### UI components & visual (antislop-ui, R-01, R-04, R-09, R-13)
- `UiAlert` maintenance kind uses `border-l-warning` (consistent with the existing warning alert variant), paired with the wrench icon in `UiStateIcon`
- Wrench icon is thematically appropriate for "maintenance" (not sparkle/star/magic generic patterns)
- Dismiss button on alert uses standard hit-target (44×44 touch area), not decorative; emits proper `dismiss` event
- Dashboard panel uses `UiPill` tone + label for state (success/warning/danger), not decorative badges
- No glow, no excessive shadow, no glassmorphism
- No layering of decorative effects

#### Accessibility & states (antislop-human, R-25, R-27, R-32)
- Dismiss button has `aria-label="Dismiss"`, not icon-only without labeling
- Alert has `role="status"` for screen reader announcement
- Input fields properly disabled (`:disabled="!!cocApi"`) while API is down; not removing interaction silently
- Dashboard panel includes three states: loading (skeleton), empty ("No calls..."), error (alert with retry)
- Disabled state on Verify/Attach inputs is explicit; no focus trap or loss of data
- Focus styling uses `focus-visible:outline-focus` with proper contrast

#### Code comments (antislop-code, R-31)
- Comments explain _why_ and _what_, not just restating obvious code:
  - `CocApiBanner`: explains session-scoped dismissal and flag-clear behavior
  - `CocApiHealthReport`: notes "it never calls the API" (key constraint)
  - `CocApiHealthData`: defines what counts as a failure (timeout, 403/429/5xx, not 404)
  - `HandleInertiaRequests::cocApiNotice()`: explains half-open state logic (next call is the probe)
- Comments are 1–2 lines per fact, written in natural developer voice
- No decorative separators, no ALL CAPS labels, no restating signatures

#### Mobile & layout (antislop-layoutmobile, R-03)
- Banner placement at top of `<main>` across all layouts (app, public, admin)
- Dismiss button sized for mobile touch (44×44 hit area visible/accessible)
- Dashboard panel uses responsive grid (`grid-cols-3`) for the three-column stat layout
- No horizontal overflow or clipping detected in viewport-scoped components

#### Direction & dials (R-37)
- `DESIGN.md` exists; dials are declared (ENERGY 2 / RHYTHM 2 / MOTION 2)
- Banner tone is consistent with "work surfaces stay clean and plain" (admin-style status notice)
- No arbitrary aesthetic choices; every component choice (icon, color, dismissal) is rooted in the spec or owner decisions
- Owner decisions from P2-10 task file are implemented as documented:
  - Maintenance kind with wrench icon (R-31: readable from shape + color)
  - Dismissal via sessionStorage while outage lasts
  - No end time in banner (admins see `openUntil` on dashboard only)
  - Dense panel format for admin work surface

#### No slop patterns detected
- No em dashes, buzzwords, or generic CTAs
- No fake data, fabricated numbers, or placeholder content disguised as real
- No decorative elements without purpose
- No decorative emoji, no excessive separators, no rule-of-three forcing
- No inline comments restating obvious code or decorative narration
- All numbers in dashboard come from real data sources (`coc_api_requests` table)
- All empty/loading/error states are labeled and perceivable
