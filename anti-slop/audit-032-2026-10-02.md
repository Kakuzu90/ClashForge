## Rationale

### Design alignment

Admin pages are intentionally plain (ENERGY 1: "clean, dense and boring — on purpose"). The System Health page follows this register exactly: semantic tokens for layout and type, no decorative motion or gradients, dense information hierarchy in tables and panels, and accessibility-first patterns.

### Copy audit (antislop-copywriting)

- **No em dashes** in user-facing text (System.vue line 83, Dashboard.vue line 152, navigation.ts line 98).
- **No AI buzzwords** ("Unlock", "Elevate", "Seamless", "Revolutionary" not present).
- **Specific copy, not generic:**
  - "Open System health" (not "Learn more", "Explore", "View details").
  - "Queues, failed jobs, the scheduler and the Clash of Clans API, as of when this page loaded." (specific, not "System overview").
  - "No jobs waiting. Every queue is empty." (plain, honesty).
  - Error titles: "Queues didn't load", "The scheduler panel didn't load" (specific, not "Error loading").
- **No fake data:** all numbers are real or from deferred props; no placeholder "10K+ users" claims.
- **formatDuration comment** (line 7–9, useDateTime.ts) states purpose clearly: "A length of time in its two largest units, e.g. how long a job has waited."

### UI audit (antislop-ui)

- **No default slop patterns:** no gradients without purpose, no glassmorphism, no excessive glow or shadow, no random border radius, no bento grids.
- **Colour:** admin UI uses semantic tokens only; state colours (danger, success, warning) paired with text labels and icons (never colour alone per R-31, decision 8 in task notes).
- **Alert pills** (System.vue lines 111–112): "Waiting over 5 min", "Over 500 waiting" — text labels explain the alert, not visual-only.
- **Components:** `AdminPanel`, `AdminTable`, `UiPill`, `UiSkeleton`, `UiAlert` are spec-aligned primitives, no new ones added. No motion beyond 80ms button press and 200ms hover (per specs/18 §7).

### Mobile & layout (antislop-layoutmobile)

- **Responsive grid** (System.vue line 121): `grid gap-4 lg:grid-cols-2` creates single-column on mobile, 2-column at lg breakpoint — mobile-first, correct.
- **Table columns** use `min-w-*` utilities with `AdminTable` component (presumed to handle overflow/scroll on mobile); this is the standard pattern used elsewhere in the app.
- **Touch targets:** buttons are 32px/40px/48px sizes per specs/18 §4; no targets below 44px visual area or without hit-area coverage.

### Keyboard & accessibility (antislop-human)

- **Semantic HTML:** `<h1>` for page title, `<dl>/<dt>/<dd>` for definitions (Failed jobs summary), `<time>` with `datetime` attributes.
- **Buttons and links:** all have real href (`system().url` via Wayfinder) or click handlers, no dead controls.
- **States:** empty states ("No jobs waiting", "No API keys configured"), loading states (UiSkeleton with label), error states (UiAlert with "Try again" button and request id).
- **Focus:** UiButton and UiPill components inherit focus styling from design system; no `outline: none` without replacement.
- **Live regions:** loading label props on UiSkeleton ("Loading queues", "Loading the scheduler panel") provide accessible context.

### Contrast (R-25)

All text uses semantic tokens from specs/18 §3:
- `--text-primary` on `--bg-page` ≈ 15.8:1 (high).
- Muted labels (`--text-muted`) on surfaces ≥ 4.5:1 (AA).
- No custom hex values; no light-grey-on-grey hallucinations.

### Direction & intentionality (R-37, R-31)

Direction: DESIGN.md states admin at ENERGY 1 (work surfaces, no flair).  
Decisions noted in task file (2026-10-02):
- Decision 8: R-31 applied — over-threshold values are text pills, never colour alone.
- Decision 9: Dashboard button text is action-specific ("Open System health").
- Nav placement: between Users and Logs per owner decision.
- `formatDuration` output format documented (2 largest units) per task scope.

## Result

**PASS.** No rule violations found. The audit and the design system align.
