# Audit 039: P2-16 Dispute Screens

**antislop active: after (project default).**

Task: [P2-16 Dispute screens for both parties](../tasks/phase-2/P2-16-dispute-screens.md)

Scope: UI and user-facing copy in dispute pages (`Disputes/Create.vue`, `Disputes/Show.vue`), dispute components (`DisputeEvidenceField.vue`, `DisputeEvidenceItem.vue`, `disputeView.ts`), updated account pages (`Accounts/Attach.vue`, `Accounts/Show.vue`, `Accounts/Verify.vue`), and backend copy (outcome labels, refusal labels, notification text, flash messages, validation messages, limiter message).

## Audit Result

**No findings.**

The dispute screens and supporting UI pass all antislop checks (R-01 to R-38, C-1 to C-5):

- **Copy is specific and clear**: All user-facing text names real actions (e.g., "You gave the account up", "Send to the admins") with no buzzwords, generic patterns, or fabricated content. Validation messages explain specific problems.
- **CTAs are action-focused**: "Verify with token", "Open a dispute", "Send to the admins", "Give the account up", "Withdraw my claim" — none are generic templates.
- **Design is intentional**: The plain "work" register (DESIGN.md, task notes line 76) is appropriate for a support process; cards, alerts, and forms are content-driven, not template-based.
- **States are complete**: The create page handles uploading, failed uploads, and refusals; the show page handles each dispute status and closed outcomes; empty evidence is shown.
- **No accessibility gaps**: Forms have labels and hints; buttons are keyboard-accessible; modals close with Escape; error states use color + text, not color alone.
- **No em dashes** (R-02) in user-facing copy.
- **All evidence** (facts, numbers, outcomes) refers to real dispute states and actions.
- **Responsive layout** uses Tailwind with no horizontal overflow; mobile-first at 375px.

The implementation follows `specs/18-design-system.md` and `DESIGN.md` direction throughout.
