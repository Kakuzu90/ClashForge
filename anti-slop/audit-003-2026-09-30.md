## Findings

1. HIGH. AppLayout.vue:36-37 (toaster at UiToaster.vue:11). R-03 (layoutmobile "Bottom Nav That Eats
   Content"). The toaster is `fixed inset-x-0 bottom-0 p-4 z-400` and each toast is `pointer-events-auto`,
   so below 768px a toast lands on top of the 56px tab bar and blocks it for its lifetime (5s, longer
   while paused on hover or focus). Fix: raise the toaster above the bar on the app layout (for
   example a `bottom-[calc(56px+env(safe-area-inset-bottom))] md:bottom-0` override passed as a class
   or CSS variable) so the nav stays reachable.

2. HIGH. app.blade.php:6 with SiteHeader.vue:10, TopNav.vue:12, PublicLayout.vue:16, AppLayout.vue:29,
   SiteFooter.vue:9, BottomNav.vue:12. R-03 (text clipped off-screen). `viewport-fit=cover` lets the page
   draw under the notch, but only the bottom inset is handled. In landscape on a notched phone the
   16/24px gutters are smaller than the side inset, so the wordmark, first nav item and content
   sit under the cutout. Fix: add `pl-[max(1rem,env(safe-area-inset-left))]` and the right
   equivalent to the header, main and footer gutters (and the tab bar), or drop `viewport-fit=cover`
   (the tab bar already works without it).

3. MEDIUM. NavIcon.vue:9-18. R-04 / R-31 (icon set by library look, reason not written). Every glyph is
   24px, 2px stroke, round caps and joins, which is the Lucide geometry, and it clashes with the
   "bold, chunky, tactile" identity in DESIGN.md. Relevance to the labels is fine; the style choice
   has no written reason. Fix: either write the reason in the comment, or draw the glyphs with a
   heavier stroke and a filled variant for the active tab (this also helps finding 5).

4. MEDIUM. SideNav.vue:16-18,36. R-19 (motion with no listed purpose; DESIGN.md MOTION 2 allows only
   spec 18 §7 motions, and that table has no sidebar row). `transition-[width]` is live during the
   post-mount localStorage read, so a user who collapsed the sidebar sees it slide from 240px to
   64px on every full page load, and the whole content column reflows with it. Fix: no width
   transition (or add the transition class only after the first toggle), and set the collapsed
   class before paint if the shift matters.

5. MEDIUM. BottomNav.vue:18. R-01 / C-4 (antislop-human "Color-Only Feedback"; spec 18 §8 "colour is
   never the only carrier of meaning"). The current tab differs from the others only by hue: gold-500
   on text-dim is 1.01:1 in luminance, so for colour-blind users the active tab is indistinguishable.
   `aria-current` covers screen readers, not sighted users. TopNav adds an underline and SideNav a
   background; the mobile bar, the primary target, has neither. Fix: add a shape cue, for example a
   2px top border or a pill behind the icon on the active tab, or a filled icon variant.

6. MEDIUM (latent, tier is Hard Gate but the slot has no consumer yet). AdminLayout.vue:23. R-03
   (layoutmobile "Fixed-Width Children"). The optional nav column is `w-52 shrink-0` with no
   small-screen behaviour, so the first admin page that fills the slot leaves about 167px for content
   at 375px. Fix: hide it below `md` behind a labelled "Menu" toggle, or stack it above `main` on
   small screens, before the first page uses the slot.

7. LOW. SideNav.vue:66,83. C-4 (announced state). The toggle changes both `aria-expanded` and its
   label ("Collapse sidebar" / "Expand sidebar"), so a screen reader hears "Expand sidebar, collapsed,
   button" and the two signals contradict each other. Fix: keep one fixed label ("Sidebar" or
   "Collapse sidebar") and let `aria-expanded` carry the state, or drop `aria-expanded` and keep the
   changing label.

8. LOW. SkipLink.vue:4 with PublicLayout.vue:16, AppLayout.vue:29, AdminLayout.vue:26. C-4 (focus not
   obscured). `#main` sits directly under a sticky 56px header (100px with the tablet nav row), but
   `main` has no scroll offset and only 24 to 32px of top padding, so a skip-link jump on a scrollable page
   puts the top of the h1 under the header. Fix: `scroll-mt-16 md:scroll-mt-[100px]` on `main`, or
   `scroll-padding-top` on `html` sized to the sticky chrome.

9. LOW. PageTitle.vue:7-11 (layouts render it at PublicLayout.vue:10 and the others). C-4 (antislop-human
   "Broken Tab Order", SPA navigation). After an Inertia visit the title updates but focus stays on the
   clicked link and nothing is announced, so a screen-reader user gets no cue that the page changed.
   Fix: on `router.on('navigate')`, move focus to `#main` (it already has `tabindex="-1"`) or update a
   visually hidden `role="status"` region with the new title.

10. LOW. config/platform.php:15 against Home/Index.vue:11. C-5 / R-38 (copy vs reality; consistency).
    The indexable default meta description says "Share and find ... base layouts, show verified player
    accounts, and recruit for your clan" as if live, while the page says "The first features are on the
    way", and the two use different words for the same thing ("player accounts" against "player
    cards"). Search snippets promise features that do not exist yet. Fix: make the description honest
    and matching, for example "Base layouts, verified player cards and clan recruitment for Clash of
    Clans players. Launching soon." and reuse the same wording on Home.

11. LOW. SideNav.vue:29. antislop-code ("Empty Labels"). `// ignore` restates what the empty catch
    already shows. Fix: give the reason ("storage unavailable: collapse state just isn't remembered")
    or delete it.

12. LOW. app.blade.php:7. C-4 / spec 18 §9 (token drift). `theme-color` hardcodes `#0e1220`. The value
    matches `--clr-navy-900` (`--bg-page`) today, but a token change will silently desync the mobile
    browser chrome. Fix: add a Blade comment naming the token it mirrors (a `<meta>` cannot read a CSS
    variable), and keep it in the token-change checklist.
